# 课程要求与交付清单

## 一、课程主线

课程以招聘就业为业务主线，要求围绕同一份岗位数据完成四类业务问题：

1. **评分**：判断岗位质量或岗位与目标画像的匹配程度。
2. **匹配**：输入简历，计算简历与岗位的匹配分并给出解释。
3. **聚类**：按照岗位类别、技能和要求发现岗位群组。
4. **大模型**：用于岗位描述总结、技能抽取、匹配解释或问答式分析。

最终成果应形成一条完整链路：数据源与需求分析 -> 数据爬取 -> 清洗与特征工程 -> 可视化 -> 评分模型 -> 人岗匹配 -> 数据看板与汇报。

## 二、第一周任务

### 1. 团队建设、选题确认、需求分析与方案设计

需要完成：

- 确定招聘就业方向和研究题目。
- 明确评分、匹配、聚类、大模型四个业务问题。
- 选定数据源并说明公开性、字段和采集方式。
- 建立 Git 仓库并初始化目录结构。
- 输出《需求分析文档》。

本项目暂定题目：

> 基于全球远程招聘岗位大数据的岗位质量评分与人岗匹配研究

### 2. 数据清洗与特征工程

需要覆盖：

- 缺失值处理
- 去重
- 字段类型标准化
- 薪资和经验文本解析
- 异常值处理
- 使用 jieba 等工具进行岗位文本清洗和分词
- 构造数值特征
- 输出《数据预处理文档》

### 3. 数据爬取实施

要求包括：

- 设计字段表。
- 使用公开、无需登录的数据源。
- 保留原始响应、岗位详情链接、采集时间和来源。
- 具备请求间隔、超时和失败重试策略。
- 分页抓取，原始数据目标不少于 12,000 条，去重清洗后有效记录不少于 10,000 条。

当前已完成 12,000 条 Himalayas API 原始记录采集，但尚未进行合并、去重和清洗。

## 三、第一周重点交付物

### 《人岗匹配文档》

应包含：

1. 简历输入处理：支持粘贴文本，说明 PDF 文本提取方案。
2. 岗位和简历文本预处理：去 HTML、统一大小写、分词、停用词处理。
3. 匹配维度与权重：技能、岗位类别、经验/职级、薪资和工作地点等。
4. 技能匹配方法：TF-IDF + 余弦相似度。
5. 匹配分公式，例如：

   `match_score = 0.55 * skill_score + 0.20 * category_score + 0.15 * experience_score + 0.10 * location_score`

6. 输出结果：总分、分项得分、匹配技能、缺失技能和解释文本。
7. 示例输入、示例输出和局限性说明。

### 《可视化分析报告》

至少输出 6 张有业务含义的图，并逐图回答“图表说明了什么、对招聘或求职有什么意义”。建议图表：

1. 岗位类别/技能词频分布
2. 薪资区间分布
3. 经验或职级与薪资关系
4. 技能组合共现网络或 Top 技能组合
5. 岗位描述长度与薪资/岗位质量关系
6. 岗位发布时间趋势或岗位类别变化趋势

报告还需要说明：

- 数据范围和清洗规则
- 指标定义
- 图表洞察
- 偏差与局限
- 后续评分模型如何使用这些特征

## 四、评分模型要求

需要完成：

- 构造岗位质量标签或匹配标签。
- 划分训练集和测试集。
- 训练并比较 Logistic Regression、SVM、Random Forest、XGBoost。
- 使用准确率、精确率、召回率、F1、ROC-AUC 等指标评估。
- 说明特征重要性或模型可解释性。

标签应有明确业务定义，例如综合岗位信息完整度、薪资信息、技能要求清晰度、经验要求合理性等形成的岗位质量等级。不能只展示模型分数而不解释标签来源。

## 五、中期汇报一 PPT

PPT 必须覆盖：

- 数据来源、采集方式和合规边界
- 数据量，目标为原始不少于 12,000 条、去重有效不少于 10,000 条
- 字段设计和清洗规范
- 至少 6 张可视化图及业务洞察
- 评分模型流程、指标和可解释性
- 人岗匹配演示：输入一份简历，返回岗位匹配分和解释
- 当前成果、问题和下一步计划

建议现场演示顺序：数据看板 -> 岗位筛选 -> 评分结果 -> 简历匹配 -> 解释模型输出。
