# 需求分析文档

## 1. 项目背景

远程招聘岗位数量快速增长，但岗位信息在薪资透明度、技能描述和工作地点限制方面差异明显。求职者需要同时判断岗位信息质量和个人技能匹配程度，招聘方需要了解岗位群体与人才供需特征。因此，本项目以全球远程招聘岗位为对象，建立从数据治理到分析应用的课程项目链路。

项目题目：**基于全球远程招聘岗位大数据的岗位质量评分与人岗匹配研究**。

## 2. 业务问题

| 业务问题 | 目标 | 当前阶段产出 |
|---|---|---|
| 岗位质量评分 | 衡量招聘信息是否完整、透明、结构清晰 | 规则质量分、二分类标签、四模型比较 |
| 人岗匹配 | 输入简历后推荐岗位并解释技能差距 | 第 2 周实现 TF-IDF + 余弦相似度 |
| 岗位聚类 | 发现技能和岗位类别形成的岗位群组 | 第 2 周实现 K-Means 与降维可视化 |
| 大模型应用 | 支持岗位摘要、问答、匹配解释和检索 | 第 2 周实现 RAG 与 Agent 原型 |

## 3. 数据源与合规边界

- 数据源：Himalayas 公开 Jobs API。
- 数据规模：600 个分页文件，原始 12,000 条岗位记录。
- 数据对象：全球远程招聘岗位；`city=Remote` 是研究对象定义，不是缺失值填充，也不代表厦门或中国本地岗位。
- 采集边界：使用公开接口和已取得的研究用途回复；不使用登录态，不处理个人简历数据，不绕过验证码或访问控制。
- 可追溯性：每条记录保留 `source_url`、`crawl_time`、`data_origin`，并记录来源页文件和行号。

## 4. 功能需求

### 4.1 数据治理

系统应能够读取分页 JSONL，按稳定岗位标识去重，解析薪资和经验，清洗文本，执行 jieba 分词，生成质量报告和教师可查看的 CSV。

### 4.2 评分分析

系统应输出岗位信息质量分、High/Medium/Low 等级，并比较 Logistic Regression、SVM、Random Forest 和 XGBoost 的 Accuracy、Precision、Recall、F1、ROC-AUC 和混淆矩阵。

### 4.3 可视化

系统至少输出岗位类别、薪资、职级、技能、描述质量、发布日期和信息质量等级等业务图表，每张图配统计口径、观察结果和业务含义。

### 4.4 后续应用

第 2 周支持粘贴简历或上传 PDF，输出匹配分、命中技能、缺失技能和解释；支持岗位聚类、RAG 召回评估和 Agent 工具调用。第 3 周再进行前后端集成和部署。

## 5. 非功能需求

- 原始数据只读，处理结果与导出结果分目录保存。
- 流程可复现，固定输入路径、随机种子和规则版本。
- 结果需说明缺失字段、跨币种限制、代理标签和样本快照偏差。
- 不联网补采，不更换数据源。

## 6. 验收标准

- 去重清洗后有效记录不少于 10,000 条。
- 所有派生记录保留三项追溯字段。
- 至少 6 张业务图和文字洞察。
- 四种评分模型均有可比较指标和可解释性材料。
- 能够向老师展示数据源、字段设计、清洗前后数量和模型限制。
