# 人岗匹配设计与实现说明

本文件记录第 2 周人岗匹配模块的实际输入处理、评分口径、可解释输出与边界。当前实现已完成本地 TF-IDF + 余弦相似度排序，不把匹配分解释为录用概率。

## 1. 输入与处理协议

- **粘贴文本**：用户在输入框粘贴简历正文；系统将其作为 UTF-8 文本传入 `match_jobs(resume_text, jobs)`，不保存原始简历到岗位数据目录。
- **PDF 简历**：命令行入口检测 `.pdf` 后调用 `extract_pdf_text()`，由 `pypdf.PdfReader` 逐页执行 `page.extract_text()`，再把各页用换行拼接后进入同一清洗流程。
- **扫描 PDF**：如果 PDF 没有可复制文本，提取结果为空；当前版本不伪造 OCR 结果，应提示“未检测到可复制文本，请上传文本型 PDF 或直接粘贴”。OCR 属于后续扩展，不计入本周已完成能力。
- **空输入与读取异常**：空文本不执行无意义排序，返回空结果；文件不存在、权限不足或 PDF 解析失败应作为输入错误提示，不改变岗位库。
- **岗位输入**：只读取 `data/processed/jobs_cleaned.parquet`，组合 `job_title`、`skills_normalized`、`broad_category/job_category` 与 `description_clean`；岗位记录继续保留 `source_url`、`crawl_time`、`data_origin`。

## 2. 文本预处理

简历和岗位文本使用相同的大小写、空白、URL、HTML/标点清洗和 jieba 分词规则。技能词先做大小写、连字符和常见同义词归一化，再进入匹配计算。当前实现的顺序为：

1. `clean_text()`：HTML 转纯文本，去除 URL、重复空白和大部分标点，保留常见技能符号。
2. `tokenize_text()`：使用 jieba 进行中英文混合分词，并过滤基础停用词。
3. `extract_skills()`：在清洗后的文本中按别名表识别技能，统一大小写、连字符和同义写法。
4. `extract_years()` 与 `infer_category()`：分别识别“X years/年”表达和岗位类别线索；识别不到时保留未知状态。

简历没有技能词时不会被直接判为“不具备能力”，而是让技能重合项为 0、文本相似度仍可由标题和描述计算，类别/经验/地点未知分项使用中性值。

## 3. 核心算法

岗位与简历文本使用 TF-IDF 向量表示，计算余弦相似度作为文本技能相关性分数。建议总分：

```text
match_score =
  0.55 * skill_score
  + 0.20 * category_score
  + 0.15 * experience_score
  + 0.10 * location_score
```

其中 `skill_score` 由 TF-IDF + 余弦相似度和标准化技能集合重合度组成；类别、经验和地点分项需要保留“未知”状态，不把缺失信息误判为不匹配。

## 4. 输出与分数语义

每个推荐岗位输出总匹配分、技能相似度、匹配技能、缺失技能、经验差异、地点限制、岗位来源和一段规则化解释。结果还保留 `source_url`、`crawl_time`、`data_origin`，以便从排序结果回溯到岗位记录。解释必须能回溯到简历词项与岗位原文，不生成无法验证的候选人评价。

`match_score` 是 0–100 的**排序参考分**，用于比较本岗位库内的相对相关性；它不是企业信誉、岗位质量分，也不是录用概率。`quality_score/quality_level` 若同时展示，只表示岗位信息的透明度与完整度。

## 5. 第 2 周验收

已准备脱敏文本演示并覆盖高匹配、部分匹配和技能缺失思路；模块测试覆盖技能别名归一化、岗位排序、Remote 地点分项、未知字段中性处理和来源字段保留。PDF 文本层与扫描 PDF 的差异通过 `extract_pdf_text()` 的空文本边界说明，未把 OCR 冒充为已完成能力。
